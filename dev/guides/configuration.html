Configuration¶

stubpy reads its options from, in order of precedence:

  1. command-line flags,

  2. the nearest stubpy.toml, or a [tool.stubpy] table in the nearest pyproject.toml,

  3. the defaults.

The search starts at the first existing target (or the working folder) and walks upward. In one folder stubpy.toml wins over pyproject.toml. --no-config skips the search.

# pyproject.toml
[tool.stubpy]
targets    = ["src/mypkg"]      # what `stubpy` and `stubpy check` act on with no paths
modules    = ["mypkg._native"]  # importable modules to stub by name
output_dir = "stubs"            # stub root
imports    = ["mypkg"]          # the standard library and mypkg may be imported
extend_exclude = ["**/_vendor/*"]

In stubpy.toml the keys are top-level; there is no [tool.stubpy] header.

# stubpy.toml
targets    = ["src/mypkg"]
output_dir = "stubs"

Keys are the field names of Config; dashes are accepted (include-private). An unknown key is an error with the closest valid name:

stubpy.toml: Unknown stubpy option 'incldue_private'; did you mean 'include_private'?

Relative targets and output_dir resolve against the folder that holds the file, not the working directory. On Python 3.10 without tomli a small built-in parser reads the subset stubpy needs (sections, strings, booleans, string arrays, comments).

What gets skipped¶

A folder target skips these by default:

Pattern

Skips

.*

Hidden files and folders.

__pycache__, build, dist, .venv, venv, .git, .tox, .nox

Caches, build output, environments and tool folders.

*.egg-info

Packaging metadata folders.

<non-identifier>

Built-in rule: folders and module files whose name Python cannot import (name copy.py, foo-bar.py, 2thing.py, backup copies).

A pattern that contains / matches the path relative to the folder target; one without matches any single folder or file name on the path. exclude replaces the defaults, and extend_exclude adds to them:

[tool.stubpy]
extend_exclude = ["tests", "mypkg/_vendor/*"]   # on top of the defaults

# or replace the defaults; this one keeps hidden folders in:
# exclude = ["__pycache__", "build", "dist", ".venv", "venv", "*.egg-info",
#            ".git", ".tox", ".nox", "<non-identifier>"]

On the command line --exclude replaces the defaults too and --extend-exclude adds to them. A file named directly as a target is always processed, so a hidden or oddly named file passed explicitly works as a loose script. Skipped files never count as failures in generate or check.

--show-excluded lists each skipped path with the pattern that matched, and --verbose prints one INFO line listing them. Report.excluded holds the (path, pattern) pairs.

$ stubpy generate . --show-excluded
excluded .hidden\x.py (.*)
excluded build\y.py (build)
excluded mypkg\core copy.py (<non-identifier>)
excluded mypkg\foo-bar.py (<non-identifier>)
wrote mypkg\__init__.pyi
wrote mypkg\core.pyi
Generated 2 stubs, 0 failed.

Docstring targets¶

stubpy docstrings (see Command line and Compiled modules) reads the stubs it acts on from the [tool.stubpy.docstrings] table when it gets no STUB and no -m. Paths are relative to the config file.

[tool.stubpy.docstrings]
packages    = ["mypkg"]    # folders searched for *.pyx / compiled modules with a same-stem .pyi beside them
import_root = "src"        # module names are relative to it; default: found by walking up __init__.py folders
overrides   = {"mypkg.core" = "stubs/core.pyi", "mypkg._old" = ""}

overrides maps a module to a stub path; an empty string drops a discovered module. In Python the table is Config(docstrings={...}), coerced to DocstringTargets.

From Python¶

Config is a frozen dataclass; every field has a default.

import stubpy
from stubpy import Config

cfg = Config(imports="none", include_private=True)   # strings coerce to the enums
cfg2 = cfg.replace(union_style="legacy")              # a validated copy
cfg3 = Config.from_dict({"include-private": True})    # a [tool.stubpy] table

stubpy.generate("src/mypkg", config=cfg)
stubpy.generate(config=stubpy.load_config())          # targets from the file

A bad value raises ValueError (unknown enum value or key) or TypeError (wrong type), naming the allowed values.

Style options¶

union_style and alias_style change how unions and alias declarations are written, with or without the import.

# aliases.py
from typing import TypeAlias, Optional, Union

Length: TypeAlias = str | float | int

class Box:
    def __init__(self, w: Length, h: Optional[Length] = None, tag: Union[str, None] = None): ...

stubpy render aliases.py (the defaults):

from typing import TypeAlias

Length: TypeAlias = str | float | int

class Box:
    def __init__(
        self,
        w: Length,
        h: Length | None = None,
        tag: str | None = None,
    ) -> None: ...

stubpy render aliases.py --union-style legacy --alias-style pep695:

from typing import Optional, Union

type Length = Union[str, float, int]

class Box:
    def __init__(
        self,
        w: Length,
        h: Optional[Length] = None,
        tag: Optional[str] = None,
    ) -> None: ...

Note

Annotations that name an alias (Length, types.Length) keep the alias name with or without the import; the style applies to the alias declaration itself. See Source and runtime.

Deprecated typing aliases are always written in their modern form: List[int] becomes list[int] (likewise Dict, Set, FrozenSet, Tuple, Type), ContextManager[str] becomes AbstractContextManager[str] from contextlib, and Callable, Iterator, Mapping, Sequence and the other abstract collections are imported from collections.abc (Pattern and Match from re). Names a module defines itself or imports from another package are left alone.

Version and platform branches¶

Module-level and class-level if statements whose tests only compare sys.version_info (>=, <, slices such as sys.version_info[:2]) or sys.platform (==, !=, startswith), combined with and, or and not, are copied into the stub with their elif and else branches, as typeshed writes them. Each branch holds the stubs of the names it defines, and the imports it needs.

# compat.py
import sys

if sys.version_info >= (3, 11):
    from typing import Self
else:
    from typing_extensions import Self

if sys.platform == "win32":
    DEFAULT_SHELL = "cmd.exe"
else:
    DEFAULT_SHELL = "/bin/sh"


class Path:
    def joined(self, part: str) -> Self: ...

    if sys.version_info >= (3, 12):
        def walk(self) -> list[Self]: ...

stubpy render compat.py:

import sys

if sys.version_info >= (3, 11):
    from typing import Self
else:
    from typing_extensions import Self

if sys.platform == 'win32':
    DEFAULT_SHELL: str
else:
    DEFAULT_SHELL: str

class Path:
    def joined(self, part: str) -> Self: ...

    if sys.version_info >= (3, 12):
        def walk(self) -> list[Self]: ...

The imported module only holds the branch the running interpreter took: that branch is introspected as usual, the others are stubbed from the source. PEP 695 syntax inside a branch (def f[T], class C[T], type X[T] = ...) is rewritten with TypeVar, Generic and TypeAlias so the stub still parses on Python 3.10. if TYPE_CHECKING: and other tests (if HAS_NUMPY:) are unchanged: the TYPE_CHECKING side is stubbed, and both sides of an unknown test are merged.

--version-branches resolve (version_branches = "resolve") keeps only the branch the running interpreter takes:

from typing import Self

DEFAULT_SHELL: str

class Path:
    def joined(self, part: str) -> Self: ...
