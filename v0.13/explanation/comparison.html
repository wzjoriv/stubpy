Where stubpy is stronger¶

  • Forwarded **kwargs and *args become real parameters, through inheritance, cls(), self.method() and function calls.

  • The live module supplies inherited and wrapped callables; the source supplies aliases, defaults, decorators and branches as written. --imports none runs without importing, and stdlib or a list limits what may be imported.

  • check is a first-class command with a diff and exit codes, and a pre-commit hook exists.

  • It has no dependencies.

Where the others are stronger¶

  • Compiled extensions. The pybind11 and nanobind generators exist for these modules and are exact for them. stubpy does not handle them yet.

  • Inference. Pyright can infer types where nothing is annotated. stubpy writes what the source and runtime show, plus literal defaults, safe return types and optional docstring types (see Inferred types).

  • Maturity. stubgen is widely used and tested against large codebases. stubpy is alpha software.

They also combine: generate stubs for compiled modules with the binding’s own tool, and generate the Python side with stubpy.
